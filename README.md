# Gold Rotation Strategy

# مشخصات کامل استراتژی معاملاتی — چرخش بین صندوق‌های طلای ایران

سند زیر خلاصهٔ کامل یک پروژهٔ تحلیل و بک‌تست هست که با یک دستیار هوش مصنوعی (Claude) روی داده‌های تاریخی ۵ دقیقه‌ای صندوق‌های طلای ایران انجام شده. هدف این سند اینه که هر هوش مصنوعی یا برنامه‌نویس دیگه‌ای بتونه بدون نیاز به خوندن کل چت، این استراتژی رو بفهمه، بازسازی کنه، و برای فوروارد تست/معاملهٔ واقعی ادامه بده.

---

## ۱. موضوع و دارایی‌ها

۶ صندوق طلای معامله‌شده در بورس ایران، با نماد فایل و بازهٔ تاریخی زیر:

| نام فارسی | نماد | تیکر فایل | بازهٔ داده |

|---|---|---|---|

| مثقال | MESGHAL | IRTK-MESGHAL-0001-5 | 2022-01-11 تا 2026-07-20 |

| کهربا | ROBA | IRTKROBA0001-5 | 2021-08-02 تا 2026-07-20 |

| طلا | TALA | IRTK-TALA-0001-5 | 2021-06-22 تا 2026-07-20 |

| مفید (طلا) | MOFD | IRTKMOFD0001-5 | 2021-06-22 تا 2026-07-20 |

| جواهر | JAVA | IRTKJAVA0001-5 | 2023-11-25 تا 2026-07-20 |

| گنج | GANJ | IRTKGANJ0001-5 | 2023-01-14 تا 2026-07-20 |

فرمت هر فایل CSV: `DATE,TIME,OPEN,HIGH,LOW,CLOSE,VOLUME` — کندل‌های ۵ دقیقه‌ای، تاریخ شمسی/میلادی به فرمت `YYYY.MM.DD`.

از ۶ صندوق، **۱۵ جفت ممکن** ساخته و همه رو تحلیل کردیم.

## ۲. آماده‌سازی داده

1. دو فایل CSV هر جفت روی `DATE+TIME` مشترک با **Inner Join** همگام‌سازی می‌شن (فقط کندل‌های زمانی که هر دو صندوق دیتا دارن).

2. `Ratio = CLOSE_A / CLOSE_B` (صندوق اول تقسیم بر صندوق دوم — ترتیب مهمه، چون این صندوق اول به‌عنوان «واحد شمارش» نهایی استفاده می‌شه).

3. فیلتر نقدشوندگی (اختیاری، در برخی نسخه‌ها استفاده شده): حجم معاملهٔ کمینهٔ دو صندوق باید بالاتر از میانهٔ متحرک ۵۰۰کندلی خودش باشه تا سیگنال پذیرفته بشه.

## ۳. تعریف دقیق استراتژی (نسخهٔ نهایی و قابل‌اجرا)

### ۳.۱ چرا این نسخه، نه نسخه‌های قبلی؟

در ابتدا استراتژی به‌صورت **جفت‌معاملاتی با فروش استقراضی (Short)** مدل شد (هم‌زمان Long یک صندوق و Short صندوق دیگه). این مدل نظری خوب کار می‌کرد ولی **در بازار واقعی ایران عملاً قابل‌اجرا نیست** چون فروش استقراضی روی واحدهای صندوق طلا برای سرمایه‌گذار خرد در دسترس نیست. بنابراین استراتژی به شکل زیر بازطراحی شد:

### ۳.۲ منطق معامله — «چرخش کامل سرمایه» (Long-only Rotation)

- میانگین متحرک سادهٔ Ratio روی پنجرهٔ **۲۰ کندل** (۵ دقیقه‌ای، یعنی ۱۰۰ دقیقه) محاسبه می‌شه: `MA20`

- انحراف درصدی: `dev = Ratio/MA20 - 1`

- **قانون:**

  - اگر `dev > +band` → کل سرمایه رو از صندوق A بفروش و صندوق B بخر (نگه‌داشتن B)

  - اگر `dev < -band` → کل سرمایه رو از صندوق B بفروش و صندوق A بخر (نگه‌داشتن A)

  - بین این دو آستانه: پوزیشن فعلی (هرچی که هست) بدون تغییر نگه داشته می‌شه — **همیشه ۱۰۰٪ سرمایه یا توی A یا توی B هست، هیچ‌وقت وجه نقد یا حالت خنثی نداریم** (به‌جز قبل از اولین سیگنال معتبر)

- دو مقدار `band` تست شده: **۰.۴٪** و **۰.۵٪** — نتایج به این پارامتر خیلی حساس نیست (نشونهٔ عدم Overfitting)، ۰.۴٪ کمی بهتر بود.

### ۳.۳ مدل کارمزد (⚠️ نکتهٔ حیاتی، دوبار اصلاح شده)

کاربر یک فایل اکسل مرجع با محاسبات دستی ارائه داد که دقیقاً باید ازش پیروی بشه:

- **خرید: بدون کارمزد.** تعداد واحد خریداری‌شده = `سرمایهٔ موجود / قیمت خرید` (دقیق و اعشاری، بدون رند کردن در محاسبات — رند کردن فقط برای نمایش/اطلاع استفاده می‌شه)

- **فروش: کارمزد ۰.۲۴٪ روی کل مبلغ فروش.**

  - `مبلغ فروش = تعداد واحد × قیمت فروش`

  - `کمیسیون = مبلغ فروش × 0.0024`

  - `سرمایهٔ جدید = مبلغ فروش − کمیسیون`

- **کل هزینهٔ هر چرخش (رفت‌وبرگشت) = فقط ۰.۲۴٪** (نه ۰.۴۸٪ — این اشتباه اولیهٔ محاسبات بود که با فایل مرجع کاربر اصلاح شد. فرض اولیهٔ اشتباه، فرض می‌کرد هم خرید هم فروش هرکدوم ۰.۲۴٪ کارمزد دارن.)

### ۳.۴ Pseudocode کامل

```python

def rotation_backtest(price_a, price_b, ma_window=20, band_pct=0.004, fee=0.0024):

    ratio = price_a / price_b

    ma = ratio.rolling(ma_window).mean()

    dev = ratio/ma - 1

    state = 0  # 0=flat (فقط قبل از اولین سیگنال), 1=hold A, -1=hold B

    holdings = []

    for d in dev:

        if not isnan(d):

            if d > band_pct:  state = -1

            elif d < -band_pct: state = 1

        holdings.append(state)

    # بازده هر کندل = بازدهٔ همون صندوقی که در حال حاضر نگه داشته شده

    # (با تأخیر یک کندل، چون سیگنال کندل i در کندل i+1 اجرا می‌شه)

    ret_a, ret_b = price_a.pct_change(), price_b.pct_change()

    held_shifted = holdings.shift(1)

    bar_ret = where(held_shifted==1, ret_a, where(held_shifted==-1, ret_b, 0))

    # کارمزد فقط لحظهٔ فروش (تغییر پوزیشن از یک حالت غیرصفر) اعمال می‌شه

    cost = 0

    for هر لحظه که pos عوض شد و prev_state != 0:

        cost = fee   # 0.0024

    # (اولین ورود از حالت flat هیچ کارمزدی نداره، چون خرید مجانیه)

    net_ret = bar_ret - cost

    equity = cumprod(1 + net_ret)

    return equity, holdings

```

### ۳.۵ نکتهٔ زمان‌بندی مهم (Timing/Lookahead Bias)

سیگنال کندل `i` روی بازدهٔ کندل `i+1` اعمال می‌شه (یعنی position یک کندل تأخیر داره تا از نگاه به آینده جلوگیری بشه). موتور بک‌تست از `position.shift(1)` برای این کار استفاده می‌کنه.

## ۴. تحلیل «واحدی» — مهم‌ترین درسِ این پروژه

سود تومانی/درصدی خام **گمراه‌کننده‌ست** چون رشد کلی قیمت جهانی طلا (که مشترک بین همهٔ صندوق‌هاست) داخلش قاطیه. برای سنجش واقعیِ «آیا استراتژی از صرفاً نگه‌داشتن یک صندوق بهتره یا نه»، باید:

1. سرمایهٔ اولیه رو به تعداد واحد صندوق **اول** هر جفت (شمارندهٔ Ratio) تبدیل کنی: `start_units = capital / price_A(t=0)`

2. ارزش پرتفوی فعال در هر لحظه (`equity_curve × capital`) رو دوباره به واحد معادل صندوق A تبدیل کنی: `equivalent_units(t) = portfolio_value(t) / price_A(t)`

3. اگه `equivalent_units` در طول زمان رشد کنه، یعنی استراتژی واقعاً از Buy & Hold بهتره. اگه کم بشه، استراتژی داره ارزش از دست می‌ده حتی اگه سود تومانی مثبت باشه.

### نتیجهٔ نهایی این تحلیل (کارمزد صحیح ۰.۲۴٪، باند ۰.۵٪، رتبه‌بندی ۱۵ جفت):

| رتبه | جفت | رشد واحد کل | Max DD٪ | دفعات رسیدن به Max DD |

|---|---|---|---|---|

| ۱ | **مثقال/گنج (MESGHAL/GANJ)** | **+904.0%** | -28.0% | 13 |

| ۲ | روبا/گنج | +888.8% | -30.7% | 13 |

| ۳ | مفید/گنج | +660.4% | -28.1% | 13 |

| ۴ | روبا/مفید | +659.2% | -32.9% | 15 |

| ۵ | طلا/گنج | +619.0% | -29.0% | 22 |

**جفت برندهٔ نهایی و انتخاب‌شده برای فوروارد تست: مثقال/گنج (MESGHAL/GANJ)** — با فاصلهٔ زیاد از بقیه، و پایدار در برابر تغییر پارامتر باند (۰.۴٪ و ۰.۵٪ هر دو همین جفت رو برنده اعلام کردن).

## ۵. یافته‌های کلیدی و هشدارها

1. **فرسایش آلفا (Alpha Decay):** بازدهی سالانهٔ همهٔ جفت‌ها به‌وضوح نزولیه. سال ۲۰۲۳ برای اکثر جفت‌ها فوق‌العاده بود (گاهی +۳۰۰٪+)، ولی از ۲۰۲۴ به بعد رشد به‌مراتب کندتر شده. این الگو در تقریباً همهٔ ۱۵ جفت دیده شد، پس احتمالاً یک تغییر ساختاری در کل بازار طلای ایرانه (نقدشوندگی بیشتر/آربیتراژگرهای بیشتر)، نه ویژگی یک جفت خاص.

2. **صندوق‌های تازه‌وارد (گنج، جواهر) هنوز کارایی کمتری دارن** و همین باعث می‌شه جفت‌های شاملشون (به‌خصوص هرکدوم با گنج) فرصت میان‌گرایی بیشتری بدن. صندوق‌های قدیمی‌تر (مثقال، کهربا، طلا، مفید) بیشتر آربیتراژ شدن.

3. **Max Drawdown واقعی بزرگه (۲۸-۳۳٪)** چون این یک استراتژی Long-only بدون Hedge هست؛ کل نوسان قیمت طلای جهانی مستقیم روی سرمایه اثر می‌ذاره (برخلاف مدل اولیهٔ Short/Long که فقط نوسان نسبیِ دو صندوق رو می‌گرفت و Max DD خیلی کوچیک‌تر، حدود ۷-۱۴٪، نشون می‌داد — آن مدل غیرواقعیه و کنار گذاشته شد).

4. **بدون Stop-loss.** تست استاپ‌لاس ۲٪ (روی مدل قدیمی Short/Long) نتیجه رو بدتر کرد چون باعث خروج زودهنگام از معاملاتی می‌شد که در نهایت برمی‌گشتن. استاپ‌لاس روی مدل چرخشی فعلی هنوز تست نشده.

5. **آزمون آماری (t-test) و Monte Carlo** روی نسخه‌های اولیه (Short/Long) نشون داد سیگنال‌ها آماری واقعی هستن، نه تصادفی (p<0.003).

6. **موتور بک‌تست یک باگ off-by-one داشت** که در اوایل پروژه پیدا و اصلاح شد (مربوط به محاسبهٔ Win Rate/Profit Factor). سود کل/Sharpe/MaxDD که مستقیم از equity curve محاسبه می‌شدن از این باگ بی‌اثر بودن.

## ۶. وضعیت فعلی فوروارد تست

- سرمایهٔ مبنا برای هر جفت در فوروارد تست: **۵۰,۰۰۰,۰۰۰ تومان**

- آخرین کندل دادهٔ تاریخی: **۲۰۲۶-۰۷-۲۰ ساعت ۱۶:۵۵**

- برای مثقال/گنج در همون لحظه: `Ratio=0.935966, MA20=0.936218, dev=-0.027%` → داخل باند، بدون سیگنال جدید (باید پوزیشن آخرین سیگنال معتبر رو نگه داشت)

### برای ادامهٔ فوروارد تست واقعی نیاز داریم به:

1. **دیتای لحظه‌ای** (کاربر اسکریپت پایتونی داره که از TSETMC قیمت لحظه‌ای + ۵ ردیف Bid/Ask هر صندوق می‌گیره)

2. اجرای مداوم/دوره‌ای منطق بالا روی این دیتا (هر ۵ دقیقه، بازسازی MA20 روی آخرین ۲۰ کندل)

3. **پیشنهاد بهبود:** به‌جای قیمت آخرین معامله، از بهترین قیمت **Ask** برای خرید و بهترین قیمت **Bid** برای فروش استفاده بشه تا اسپرد واقعی بازار هم لحاظ بشه (این هنوز پیاده‌سازی نشده)

4. چون محیط تحلیل فعلی (Claude.ai sandbox) دسترسی شبکه نداره، اجرای زنده باید با **Claude Code** (که روی سیستم کاربر با دسترسی کامل شبکه اجرا می‌شه) یا هر ابزار دیگه‌ای که بتونه اسکریپت پایتون کاربر رو صدا بزنه، انجام بشه.
